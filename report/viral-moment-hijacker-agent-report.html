01Agent Concept Brief

▸ The marketing problem

When a food trend blows up on TikTok, the window to join it is measured in hours, not days. The manual workflow (spot the trend, research creators, write outreach, draft a post, email customers) takes a team days. By then, the audience has moved on.

The real bottleneck is speed of coordination: every step is easy on its own, but chaining them fast enough is not. This agent runs the whole chain automatically.

▸ Target user

Small social and influencer marketing teams (1 to 3 people) at consumer brands chasing Gen Z and millennial audiences. The agent works for any brand in a category where viral content is frequent enough to be worth monitoring — food, beauty, fitness, fashion, and beyond.

Our demo brand is Forkly, a fictional meal kit company with a casual, witty voice. Food was a strategic category choice: food content goes viral constantly, so almost any trend can be credibly converted into a Forkly kit.

▸ From one command to a full campaign

input → reasoning → output → value
Input

One command with the brand profile: industry, name, description, platform, tone, and values. No human input during the run.

→
Reasoning

A Gemini 2.5 Flash orchestrator decides like a strategist: which trend has the best opportunity, which angle feels authentic, not forced, and how to personalize each pitch.

→
Output

A complete campaign package: ranked trend analysis, scored influencer shortlist, personalized DM per creator, brand post, hashtag strategy, 7-day calendar, and a customer email.

→
Business value

Work that takes a team 1 to 2 days is done in 2 to 5 minutes for roughly $0.01 to $0.05 in API cost per campaign (Gemini 2.5 Flash pricing).

▸ Why it supports decision-making

The agent never just hands over copy. Every campaign ships with the reasoning behind it: opportunity scores per trend, a why-good-fit note per creator, and an explicit brand-angle justification. A marketer can reject the strategy and still keep the research. It is a decision-support package, not a black box.

Deliverable 2 · Part A

02How It Works

One orchestrator, three sub-agents, ten chained steps. The orchestrator receives analyzed reports, never raw scraped data, so its context stays focused on strategy.

▸ Multi-agent architecture

Orchestrator
gemini-2.5-flash
Strategy · brand angle · DM pitches · brand post · calendar
TrendResearchAgent
search_viral_trends
Scrapes live platform data via Apify, ranks trends by opportunity score and suggests content angles.
gemini-2.5-flash
InfluencerAgent
find_influencers
Scrapes real creator profiles, scores each on niche fit, returns matches with a why-good-fit note.
gemini-2.5-flash
EmailAgent
send_customer_email
Writes the full customer email (subject, body, CTA) from trend context, then simulates the send.
gemini-2.5-flash

Why split it? Each agent has one job and a focused context. All three sub-agents use the same model (Gemini 2.5 Flash) — one API key, one provider — while separation of concerns keeps each agent's system prompt minimal and its output predictable.

▸ Agents are called on demand — not all at once

Because each sub-agent is an independent API call, the orchestrator decides which agents to invoke and when, based on what the campaign actually needs. This is the core reason three focused agents are more powerful than one big prompt: any subset can run in any order, without touching the others.

selective calling · Forkly examples
  • APITCH ONLYTeam spots a trend manually → call InfluencerAgent only. Skip research and email. Forkly: it's Saturday, the Cane's sauce moment is everywhere — just need a scored creator list in 30 seconds. flash × 1
  • BEMAIL BLASTTrend is already picked → call TrendResearchAgent + EmailAgent. Skip influencer outreach. Forkly: the Copycat Kit is already live, just needs a customer email to match the food moment. flash × 2
  • CFULL RUNAll three sub-agents fire in sequence: scrape trends → score creators → write email copy. Forkly: standard reactive campaign from scratch. flash × 3

▸ The 10-step pipeline

pipeline.run
  • 01DISCOVERTrendResearchAgent scrapes live data, ranks trends by opportunity real
  • 02IDENTIFYInfluencerAgent scores real creator profiles for niche fit real
  • 03STRATEGIZEOrchestrator picks the angle, flags it if the fit feels forced real
  • 04HASHTAGSGrouped strategy: broad + niche + branded + trend, with a caption formula real
  • 05PERSONALIZECustom DM per creator referencing their actual recent posts real
  • 06CREATEReactive brand post in Forkly's voice, platform-native format real
  • 07CALENDAR7 days: day 1 jumps on, days 2 to 5 sustain, days 6 to 7 convert real
  • 08POSTPublishes the brand post to the social account simulated
  • 09EMAILEmailAgent writes subject, body and CTA, then sends to the list send simulated
  • 10SAVEFull campaign package persisted to output/ as timestamped JSON real

Publishing and email sending are simulated because real platform APIs require verified business accounts and OAuth. In production you would swap the simulation blocks in tools.py for real API calls. Everything else stays identical.

Deliverable 2 · Part B

03Technical Design & Spec

Built with spec-driven development in Claude Code: the behavior was defined in specifications first, then implemented and iterated against them.

▸ The specification: CLAUDE.md

The project's source of truth is a CLAUDE.md spec file that Claude Code reads on every session. It pins down the architecture, the 10-step workflow, the multi-agent pattern, and the Forkly brand context. This is how we kept Claude Code building our concept instead of drifting into generic output.

▸ Prompt structure: the orchestrator

The orchestrator's system prompt is built dynamically from the CLI input. It has four blocks: Brand (injected identity), Sub-Agents (who it can delegate to), Mission (the 10 ordered steps), and Quality Rules. Excerpt:

src/agent.py · system prompt (excerpt) 
# Sub-Agents You Coordinate
You do not work alone. Three specialized AI agents handle
the data-heavy and writing tasks:
EmailAgent: called via send_customer_email. Writes the full
customer email and simulates sending it. Just provide
trend_name, trend_summary, and brand_angle.
Do NOT write the email yourself.

# Quality Rules
· DMs must be warm, specific, and platform-native.
  No "I came across your profile" openers.
· Authenticity over virality. If the angle feels
  like a stretch, say so.

The key design move: the orchestrator is explicitly told what not to do. It never writes the email, never sees raw scraped data. Delegation is enforced in the prompt, not just hoped for.

▸ Tool definitions

Seven tools are defined as JSON schemas in src/tools.py. Three dispatch to sub-agents (their own Gemini API call), four run directly. Example:

src/tools.py · tool schema (excerpt) 
{
  "name": "search_viral_trends",
  "description": "Delegate to the TrendResearchAgent ...
    scrapes live data via Apify, then analyzes and ranks
    trends by opportunity score. Returns pre-analyzed
    results with content angles, not raw hashtag data.",
  "input_schema": {
    "industry":  { "type": "string" },
    "timeframe": { "enum": ["last 24 hours",
                   "last 48 hours", "this week"] }
  }
}

▸ Development process & iterations

  • Iteration 1 · Ideation
    From generic to original

    Early concepts felt like single-function tools, too simple and too isolated. We pushed until the concept chained many actions around one complete problem: speed-to-trend. Food was chosen so the demo brand could credibly react to almost any trend.

  • Iteration 2 · First build
    Redirecting Claude Code with CLAUDE.md

    Claude Code's first outputs drifted generic. The fix: a detailed CLAUDE.md spec defining the exact 7-step pipeline plus the Forkly brand context, so every session built against our concept.

  • Iteration 3 · Architecture upgrade
    Single agent → multi-agent

    We split the monolithic agent into an orchestrator + 3 sub-agents, each with a focused prompt and the cheapest model that does the job well. The orchestrator now reasons over clean reports instead of raw scrapes.

  • Iteration 4 · Hardening
    Standalone entry points + per-task docs

    Each sub-agent got its own CLI entry point so it can be tested in isolation, and every step got a spec doc in docs/agents/. We also added JSON fallback handling after sub-agents occasionally prefixed their responses with text.

Deliverable 4

05Reflection

A post-campaign retro: what ran clean, what threw warnings, and what we would patch next.

▸ What the agent does well

run.log · strengths
End-to-end chaining. Ten steps from one command: research, scoring, strategy, copy, distribution, persistence. One complete problem, not one isolated task.
Real data, real reasoning. Trends and profiles are scraped live, so pitches reference a creator's actual posts, not placeholders.
Right agent per job. Three focused sub-agents on Gemini 2.5 Flash — one for trend analysis, one for influencer scoring, one for email copy. One provider, one API key, quality where it matters.
Explainable output. Opportunity scores, fit notes, and angle reasoning ship with every campaign. Marketers can audit, not just accept.
Honesty guardrail. The orchestrator flags forced trend-brand connections instead of writing inauthentic copy.

▸ Limitations

run.log · known issues
Distribution is simulated. Posting and email return fake confirmations; real APIs need verified business accounts.
No human approval gate. The pipeline runs fully autonomously, which no real company should accept for publishing.
Scraping fragility. Apify cold starts can hang, and data quality varies by platform and time of day.
One-shot, not continuous. A human still decides when to run it; it does not monitor 24/7.
Occasional JSON errors. Sub-agents sometimes prefix their JSON with text, causing parse failures. The EmailAgent has a fallback; others need a re-run.
No feedback loop. The agent never learns whether its campaigns actually performed.

▸ Risks & ethical considerations

RiskWhy it mattersMitigation
disclosureAI-written DMs read as personal. Creators who find out may feel deceived, damaging the very relationship the outreach builds.Disclose AI assistance; a human sender stays accountable for every DM.
trend hijackingNot every viral moment should be marketed on. Trends tied to tragedy or conflict make brand content offensive.Brand-safety filter plus mandatory human review on sensitive topics.
scraped dataCreator profiles are collected without consent; scraping may breach platform terms even for public data.Prefer official APIs in production; store only what outreach needs.
hallucinationA DM that "references" a post the model misread or invented exposes the automation instantly.Ground pitches in verbatim scraped data; human spot-check before sending.
email consentTrend-triggered emails could exceed the frequency subscribers consented to, risking spam complaints and GDPR issues.Frequency caps, consent-based segments, one-click unsubscribe.

▸ Use in a real marketing context

Deployed honestly, this agent is a first-draft machine for the trend desk, not an autonomous publisher. The realistic setup: it monitors continuously, and when a trend crosses the threshold it drops a complete draft campaign into the team's review queue.

The humans then do the two things the agent cannot: judge whether the brand should join this conversation, and own the relationships with creators and customers. That split keeps the speed advantage while keeping accountability with people.
